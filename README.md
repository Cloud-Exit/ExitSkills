# ExitSkills

ExitSkills is free and open-source software that discovers public GitHub repositories containing `SKILL.md` or `SKILLS.md` and rejects repositories with 10 stars or fewer. When an OpenAI-compatible endpoint is configured, every skill must receive an explicit passing security and quality assessment with both scores at least 5/10 before publication. Deployments that omit both AI settings publish skills without LLM enforcement. It implements the skills.sh catalog API under both the documented `/api/v1` prefix and the shorter `/v1` prefix used by `skills.exitmesh.com` clients.

## What it does

- Enumerates every repository listed in the live skills.sh official catalog, then searches additional star-ranked public repositories whose README mentions `SKILL.md` or `SKILLS.md`. It recursively finds those exact filenames at any depth and supplements both passes with exact filename code search. Repositories with 10 stars or fewer are rejected before their skill content is downloaded.
- Skips GitHub content downloads, AI assessments, and database writes for stored skills updated less than 24 hours ago; skills exactly 24 hours old are eligible again.
- Uses the live [skills.sh official catalog](https://www.skills.sh/official) both to enumerate official repositories and to categorize their creators; unofficial skills have identical indexing eligibility.
- Stores skill metadata, file snapshots, SHA-256 content hashes, audit results, security scores, and quality scores in PostgreSQL or SQLite.
- Removes an existing skill when a later assessment scores either security or quality below 5/10. Quality checks reject placeholder, spammy, incoherent, misleading, incomplete, or non-actionable skills.
- With LLM enforcement enabled, fails closed by removing an existing skill when a completed assessment errors or the model does not return `status: pass`. Canceled and timed-out requests remain unchecked and are retried instead of being treated as rejections.
- Requires encrypted, expiring bearer API keys generated by the `admin` executable.
- Exposes master-authenticated API-key administration and per-skill download statistics.
- Applies a configurable per-key, per-pod sliding-window rate limit (600 requests/minute by default).

The compatibility `installs` field is populated from GitHub stars because this service does not receive skills.sh installation telemetry. Consequently, `all-time`, `trending`, and `hot` currently share the same star-ranked ordering. Discovery begins with the repository identities embedded in the official catalog, loads their GitHub metadata, and recursively examines every eligible default-branch tree. It then calls GitHub repository search with `(SKILL.md OR SKILLS.md) in:readme stars:>10`, ordered by stars descending, which ensures high-star unofficial repositories such as `JuliusBrussee/caveman` are considered even when GitHub code-search relevance omits them. The complementary code search processes every exact match available within GitHub's 1,000-result-per-query ceiling. GitHub's filename qualifier can return near-matches such as `hard-skills.md`; these are discarded before any content requests.

GitHub primary and secondary rate limits are coordinated across concurrent workers. The client uses `X-RateLimit-Remaining`, `X-RateLimit-Reset`, `X-RateLimit-Resource`, and `Retry-After` rather than assuming one fixed quota, so the same behavior covers authenticated and unauthenticated limits as well as the separate code-search bucket. When a quota is exhausted, indexing logs the resource and reset time, waits without blocking the API server, and retries. Repeated secondary-limit failures eventually fail the indexing run instead of silently recording affected skills as unavailable.

## GitHub authentication

For global public-repository indexing, use OAuth App client credentials. This is server-to-server HTTP Basic authentication for public GitHub API data; it does not perform a user authorization flow and does not require repository scopes or GitHub App permissions. An OAuth App owned by a GitHub Enterprise Cloud organization receives GitHub's higher per-app public-data quota.

```sh
GITHUB_CLIENT_ID=your-oauth-app-client-id
GITHUB_CLIENT_SECRET=your-oauth-app-client-secret
```

Complete OAuth credentials take precedence when a legacy `GITHUB_TOKEN` is also present, making migrations safe when the token is still inherited from a shell or Secret. The legacy bearer-token mode remains available for local use and existing deployments. Startup logs `github authentication configured` with `mode=oauth_app` or `mode=token`, without logging credential values. Rate-limit warnings use the same non-secret mode name so the active quota is visible operationally.

## Requirements

- Go 1.26.5 for local development and release builds
- No external database for local development; SQLite is embedded in the Go binary
- PostgreSQL 14 or newer for production and multi-replica deployments
- A GitHub OAuth App client ID and client secret for the independent public-data quota, or a legacy GitHub token with public-repository read access
- A 32-byte encryption key, base64 encoded
- A random master token of at least 32 bytes for the `/v1/admin/*` API
- Optionally, an OpenAI-compatible chat-completions endpoint and model for enforced assessment

For production, generate the encryption key once and keep it stable; changing it invalidates API-key authentication and prevents stored key ciphertext from being decrypted:

```sh
openssl rand -base64 32
```

For local development, copy `.env.example` and populate the GitHub and AI settings. `make run` automatically loads `.env`; no manual `export` step is required. Then:

```sh
make test
make run
```

`make run` always sets `DATABASE_URL` from `LOCAL_DATABASE_URL`, which defaults to `sqlite://.local/skills.db`. It therefore ignores any production `DATABASE_URL` left in `.env`, creates `.local/`, creates the SQLite database file, and applies migrations automatically. The local admin target loads the same `.env` and uses the same database:

```sh
make admin NAME=local-client VALID_FOR=24h
```

Override the local path explicitly when needed:

```sh
make LOCAL_DATABASE_URL=sqlite://.local/alternate.db run
```

The `run` target also forces `INDEX_ON_START=true`: after startup it immediately refreshes the skills catalog, then continues refreshing at `INDEX_INTERVAL` (24 hours by default). This override applies only to `make run`.

Indexing uses bounded batches: discovery produces at most 10 candidates, audits and stores that batch, releases its contents, and only then continues. Boot-time LLM reconciliation likewise reads 10 compact records at a time rather than loading the entire unchecked catalog. Supporting files are capped at 4 MiB per skill; binary, invalid UTF-8, and NUL-containing files are rejected before persistence. An invalid candidate is counted as failed without aborting later batches. The container image and Compose deployment default `GOMEMLIMIT` to `384MiB`; the Helm chart exposes the same default as `config.goMemoryLimit`, leaving runtime and HTTP-serving headroom beneath its default 512 MiB container limit. Keep this setting below the container memory limit when overriding resources.

Each refresh logs `indexing started` before any GitHub or AI work, with `trigger=startup` or `trigger=schedule`. The matching completion or failure log includes the same trigger and elapsed duration.

At the default `LOG_LEVEL=info`, indexing logs official owner and repository counts, official repository metadata/tree progress, ranked and code-search page progress, each 10-candidate audit/store batch, a 30-second heartbeat while a page is still being processed, fresh-skill skips, and cumulative stored/rejected/failed totals. Boot-time reconciliation also logs each 10-skill batch plus the start and outcome (`passed`, `rejected`, or `failed`) of every stored-skill LLM assessment, including its skill ID, position, total, scores when available, and duration. A canceled or timed-out AI request is logged as retrying and leaves the skill unchecked instead of deleting it; retries continue while the service context is active. Candidate downloads and AI assessments run with bounded concurrency (`INDEX_CONCURRENCY=8` by default). Set `LOG_LEVEL=debug` in `.env` to add per-skill discovery, security score, quality score, indexing, and skip-reason logs. Skill contents and credentials are never logged.

```sh
LOG_LEVEL=debug make run
```

The local database persists across `make run` and `make clean`; remove `.local/skills.db` explicitly when you want a fresh catalog.

For convenience, `make run` and `make admin` accept an arbitrary local `ENCRYPTION_KEY` passphrase such as `test` and derive a stable 32-byte key with SHA-256. This behavior is guarded by `EXITMESH_LOCAL_DEVELOPMENT`, which the Make targets set themselves. Direct binary, container, and Helm startup remain strict and require the production base64 format; do not enable local-development mode in a deployment.

Database migrations run automatically on service and admin startup for both backends.

With AI configured, the HTTP listener starts before boot reconciliation so health checks and already-approved catalog entries remain available throughout indexing. Catalog list, search, detail, curated, and audit queries filter out every row whose `llmChecked` flag is false. Boot reconciliation processes those unchecked rows before any GitHub discovery: explicit passes become visible, rejections are removed, and interrupted requests remain hidden while retrying. This includes rows created by older versions and rows collected while AI was disabled. With AI disabled, this boot phase is skipped and unchecked skills remain publishable.

## Database backends

SQLite and PostgreSQL implement the same skill catalog, search, curated listing, audit snapshot, and encrypted API-key operations.

```sh
# SQLite file, created automatically
DATABASE_URL=sqlite://.local/skills.db

# Shared production PostgreSQL
DATABASE_URL=postgres://skills:change-me@postgres:5432/skills?sslmode=require
```

SQLite is intended for local testing and single-instance deployments. It uses WAL mode, a busy timeout, and one database connection per process. Use PostgreSQL when running multiple service replicas or when the database must be shared across pods.
SQLite database files are created with owner-only (`0600`) permissions.

| `REQUEST_TIMEOUT` | no | `30s` | GitHub, skills.sh, and AI HTTP timeout |
| `GITHUB_API_BASE_URL` | no | `https://api.github.com` | HTTPS GitHub API base, overridable for tests/enterprise |
| `OFFICIAL_SKILLS_URL` | no | `https://www.skills.sh/official` | HTTPS official-creator catalog |

¹ The server requires these values; the `admin` executable requires only the database and encryption key. Local Make targets override the database with `LOCAL_DATABASE_URL`, supply a development-only encryption passphrase, and give `make run` a development master token when those values are unset.

² Configure both OAuth App variables, or `GITHUB_TOKEN`. Complete OAuth credentials take precedence if a legacy token is also present. OAuth client credentials are sent only to `GITHUB_API_BASE_URL` and are never logged.

³ Configure `AI_BASE_URL` and `AI_MODEL` together to enable enforced LLM assessment. Omit both to disable it. A partial configuration is rejected at startup. `AI_API_KEY` remains provider-dependent.

## Create API keys

Both binaries are placed in `/usr/local/bin` in the image, so `admin` is directly available inside a running pod. The plaintext token is printed once; the database stores an HMAC lookup and an AES-256-GCM ciphertext, never plaintext.

```sh
kubectl exec deployment/exitskills -- \
  admin --name automation --valid-for 720h
```

The equivalent explicit subcommand forms are also accepted:

```sh
admin create-api-key --name automation --valid-for 24h
admin api-key create --name automation --valid-for 24h
```

API keys can also be created and revoked over the admin API. Admin routes require `MASTER_TOKEN` as their bearer credential; ordinary API keys cannot access them. The master credential can also read catalog endpoints for bootstrap and diagnostics, but those reads are not counted as client downloads. `validFor` uses Go duration syntax and defaults to `720h`.

```sh
curl -X POST 'https://skills.exitmesh.com/v1/admin/token' \
  -H "Authorization: Bearer $MASTER_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"automation","validFor":"24h"}'

curl -X DELETE 'https://skills.exitmesh.com/v1/admin/token' \
  -H "Authorization: Bearer $MASTER_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"id":"key_REPLACE_ME"}'
```

Creation returns `201` with `id`, `name`, `expiresAt`, and the plaintext `token`. The token is shown once. Revocation returns `204`; keys are retained as revoked records so historical usage remains attributable by key ID and name.

`GET /v1/admin/stats` returns every indexed skill, including skills with zero downloads. A download is counted after a normal API key successfully fetches `GET /v1/skills/{owner}/{repo}/{skill}`. Results include total downloads, unique API-key clients, last-download time, and per-client ID/name/count/first/last timestamps. Plaintext API keys, the master token, IP addresses, and authorization headers are never stored in these statistics.

```sh
curl -H "Authorization: Bearer $MASTER_TOKEN" \
  'https://skills.exitmesh.com/v1/admin/stats'
```

The `/api/v1/admin/*` aliases are also supported. Usage collection begins after this schema migration; requests made by older versions are not reconstructed.

## API

Every catalog endpoint requires `Authorization: Bearer <token>`. Skill objects include `llmChecked`. Passed skills also include `securityScore` and `qualityScore` values in the 5–10 range; unchecked skills from AI-disabled deployments omit both scores. Responses include `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Reset`; exhausted clients receive `429` plus `Retry-After`.

| Endpoint | Description |
|---|---|
| `GET /api/v1/docs` | Unauthenticated Redoc API reference embedded in the server binary |
| `GET /api/v1/skills` | 0-based paginated catalog; `view`, `page`, `per_page` |
| `GET /api/v1/skills/search` | Search by `q`, optional `owner`, and `limit` |
| `GET /api/v1/skills/curated` | Official skills grouped by creator |
| `GET /api/v1/skills/{owner}/{repo}/{skill}` | Skill snapshot and content hash |
| `GET /api/v1/skills/audit/{owner}/{repo}/{skill}` | ExitSkills AI assessment with security and quality scores |
| `POST /api/v1/admin/token` | Create a named, expiring API key using `MASTER_TOKEN` |
| `DELETE /api/v1/admin/token` | Revoke an API key by ID using `MASTER_TOKEN` |
| `GET /api/v1/admin/stats` | Download totals and per-key usage for every skill using `MASTER_TOKEN` |

All routes are also available without `/api`, for example:

```sh
curl -H 'Authorization: Bearer em_sk_REPLACE_ME' \
  'https://skills.exitmesh.com/v1/skills?per_page=20'
```

Unauthenticated Kubernetes probes are available at `/healthz` and `/readyz`.

## Security controls

Production startup rejects plaintext outbound GitHub, official-catalog, and AI endpoints, URLs containing embedded credentials, and URLs containing queries or fragments. HTTP endpoints are accepted only when `EXITMESH_LOCAL_DEVELOPMENT=true`. The outbound client does not follow redirects, preventing bearer or OAuth credentials from being moved to a different origin or downgraded to plaintext transport.

When enabled, the AI assessor treats every skill as untrusted data, separately scores security and quality, validates and bounds the model's structured result, and never includes an upstream AI response body in logged errors. Missing quality output or a non-`pass` status is an assessment failure, not an implicit pass. Newly discovered candidates are not written to the catalog until this gate succeeds. API tokens must have the exact generated `em_sk_` shape before a database lookup is attempted. HTTP responses include restrictive content, framing, referrer, and browser-permission headers; request headers and search inputs are bounded.

The Compose application binds to loopback by default and runs with a read-only root filesystem, no Linux capabilities, and `no-new-privileges`. The Helm chart additionally defaults to `RuntimeDefault` seccomp confinement. Keep secrets outside the repository, use a TLS-enabled PostgreSQL connection in production, and rotate the master and provider credentials if exposure is suspected.

## API documentation

The OpenAPI 3.1 source contract is [`docs/openapi.json`](docs/openapi.json). Generate a standalone HTML reference with the pinned Redoc renderer:

```sh
make docs
```

The generated file is `dist/api-docs/index.html`. The same reference is served without authentication at `http://localhost:8111/v1/docs` and its `/api/v1/docs` alias; its OpenAPI contract is embedded in the server binary, so the route also works in the container. The standalone file embeds the OpenAPI document and can be opened directly. Both forms load Redoc from its official CDN. Override the output directory or pinned renderer release with `API_DOCS_DIR` and `REDOC_VERSION` when needed. Update the OpenAPI contract whenever routes or payloads change.

## Deployment

The multi-stage `Dockerfile` builds static Go executables with Go 1.26.5 and runs them as an unprivileged user on `alpine:latest`. Both base-image tags are locked to reviewed multi-platform digests so builds do not silently change; update the tag and digest together during a deliberate dependency upgrade. Supported deployment paths are:

- A single Docker container with persistent SQLite.
- Docker Compose with PostgreSQL 18 and persistent storage.
- Kubernetes using the included Helm chart and an existing PostgreSQL database.

See the complete [Docker, Docker Compose, and Kubernetes deployment guide](docs/deployment.md) for secret generation, startup, API-key creation, upgrades, and backups.

## CI and releases

Pull requests and non-main pushes run formatting, vet, race-enabled tests, builds, and Helm linting. Every push to `main` creates the next patch release in the chart's SemVer line (currently `1.0.x`), publishes versioned and `latest` images to GHCR, publishes the `exitskills` chart to `oci://ghcr.io/cloud-exit/charts/exitskills`, and creates a `vMAJOR.MINOR.PATCH` GitHub release containing the two binaries and chart archive.

Development follows mandatory TDD. Update this README whenever behavior, setup, configuration, APIs, or operations change.
